### II. AGENDA AND DISCUSSION

#### 1. Project Repository
A GitHub repository for the project has been created. The repository details were made available to the members.

Members were asked to provide their GitHub usernames and associated email addresses to facilitate invitations and access to the project repository.

#### 4. Assignment of Roles
The Project Manager (PM) assigned roles to members based on the project's requirements. Some roles were subsequently adjusted according to members' responses and availability.
* Radz Moreno and Evan Magadan exchanged assigned roles.
* Other assignments remained as initially designated by the PM.

#### 5. Milestones, Issues, and Project Workflow
The PM discussed the project's milestones, issues, rules, guidelines, and overall workflow to ensure that all members were informed of the expected procedures.
The complete rules and guidelines were posted in the appropriate Discord and GitHub channels for members' reference.

The following workflow updates were discussed:
* **To Do → In Progress:** Members should draft detailed specifications based on the rules and guidelines posted in GitHub.
* **In Progress → Done:** Members should create a draft pull request (PR) according to the specified requirements, make the necessary updates, and submit the PR for review.
* A PR must be approved by either the Project Manager or the designated Leader before the task can be moved from In Progress to Done.

#### 6. First Milestone
The tasks included under the First Milestone have already been added to the To Do section by the PM for the members' information and reference.
Members were advised to review the listed tasks and follow the established workflow when working on them.

#### 7. GitHub Best Practices
The group reviewed the following GitHub practices that all members are expected to follow:
* Do not create pull requests directly to `main`.
* Always branch out from `dev` when working on new features.
* Always pull the latest changes before creating a pull request.
* Pull requests must follow the established review and approval process before being marked as completed.

#### 8. Communication Channels
Discord was established as the primary communication platform for the project. The following channels and their respective purposes were discussed:

| Channel | Purpose |
| :--- | :--- |
| `#announcements` | Official project announcements and important updates. |
| `#rules-and-guidelines` | Project rules, guidelines, and definitions. |
| `#task-assignments` | Task assignment notifications through the webhook. |
| `#documentation` | Student profiles and project documentation. |
| `#general` | General discussions and conversations. |
| `#meeting` | Conducting project meetings. |
| `#code-review` | Submission and discussion of pull requests; members should send the PR link and mention the assigned reviewer. |
| `#branch-updates` | Tracking members' branch activities and work time. |
| `#dev-discussion` | General development-related discussions. |
| `#github-logs` | GitHub issue and repository notifications. |
| `#backend` | Backend-specific development discussions; access limited to assigned members. |
| `#frontend` | Frontend-specific development discussions; access limited to assigned members. |
| `#report-bugs` | Reporting bugs with adequate descriptions and relevant details. |
| `#bug-fix` | Reporting when significant or specific bugs have been fixed. |

*Access to the Backend and Frontend channels will be limited to members assigned to the respective areas.*

### III. DECISION MADE
The following decisions were established during the meeting:
1. Saturday was selected as the regular weekly meeting day, receiving 8 out of 11 votes.
2. Discord will serve as the project's primary communication platform.
3. Members must follow the established GitHub branching and pull request workflow.
4. Pull requests must be reviewed and approved by the PM or designated Leader before tasks are marked as completed.
5. The First Milestone has been added to the project's To Do list.
6. Dedicated communication channels will be used for project management, development, documentation, code review, bug reporting, and other project activities.
