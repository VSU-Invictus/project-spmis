### I. CALL TO ORDER
The twelfth weekly project meeting was called to order at 8:30 PM through Discord. Ten of the eleven members were present, meeting the required quorum. No meeting was held during the preceding week, resulting in a one-week gap in the regular meeting schedule. Most members were occupied with their respective development tasks, and there were no significant matters requiring a separate discussion at the time, as work primarily focused on the ongoing implementation of Milestones 3 (Backend) and 4 (Frontend). The regular meeting resumed to discuss the remaining development timeline, application testing, and quality assurance preparations.

### II. AGENDA AND DISCUSSION

#### 1. Development Deadlines and Code Freeze Reminders
The Team Leader (TL) reiterated the remaining project deadlines and emphasized the importance of completing the outstanding development work before the scheduled code freeze.

The following reminders were discussed:
* **Code Freeze:** Beginning November 25, 2026, regular feature development must stop, with only bug fixes permitted.
* **Final Changes Deadline:** December 3, 2026, was identified as the final cutoff for changes, with subsequent modifications restricted to necessary bug fixes.
* **Project Presentation:** The final project presentation is scheduled for December 4, 2026.
* **Development Progress:** The TL noted that the project was nearing completion, with most remaining concerns primarily involving the frontend implementation.

#### 2. Application Run-through and Individual Testing
The team discussed the procedures for running and testing the SPMIS web application locally to identify remaining issues before the development freeze.

The following instructions were provided:
* **Environment Configuration:** Members were reminded that two environment configurations are available through the team's Discord server, including a configuration for local development. These must be properly set up before running the application.
* **Frontend Development Server:** Members were instructed to run the following command to launch the website locally:

  `npm --prefix app run dev`

* **Mock Backend Testing:** Members may temporarily comment out or adjust the appropriate environment configuration entries to test the application using the mock backend, following the provided setup instructions.
* **Mock Server:** The following command was shared for running the mock backend:

  `npm --prefix app run mock:server`

* **Individual Testing:** Members were encouraged to run through the application themselves and identify functionality that may require corrections before the final development deadlines.

#### 3. Quality Assurance Assignments and Bug Resolution
The team discussed the remaining quality assurance responsibilities, particularly the verification of frontend features and the identification of broken endpoints or routes.
* **Application Testing:** The QA Team was tasked with testing the website and identifying functional issues, including broken frontend routes, endpoints, and other affected features.
* **Issue Documentation:** Identified bugs must be documented through the necessary GitHub Issues to facilitate tracking and assignment.
* **QA Deadline:** The QA Team was expected to prepare the identified issues by November 23, 2026.
* **Bug Resolution Deadline:** All identified bugs were targeted for resolution by Wednesday, November 25, 2026, in preparation for the development freeze.

### III. DECISION MADE
* The code freeze will begin on November 25, 2026, with further development restricted to bug fixes.
* December 3, 2026, was established as the final changes deadline, with the project presentation scheduled for December 4, 2026.
* Members will conduct individual application testing using the provided development environment configurations and, when necessary, the mock backend.
* The QA Team will review the application's functionality and create the necessary GitHub Issues for identified bugs by November 23, 2026.
* All identified bugs are targeted for resolution by November 25, 2026, particularly those affecting frontend routes, endpoints, and application functionality.
